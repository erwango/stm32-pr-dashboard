Rules

  • Population: PRs in zephyrproject-rtos/zephyr labelled platform: STM32.
  • Drafts are absent by construction: the upstream assigner workflow only labels PRs that are ready for review, so a PR enters this dataset when it is labelled.
  • Area = each area: label on the PR. A PR with three area labels counts in all three, so the sum over areas exceeds the PR count. A PR without an area: label is shown as Unclassified.
  • Age is measured from the platform: STM32 labeling event ("waiting for ST review"), not from PR creation, so long draft periods do not count.
  • Stale means no activity for more than 30 days.
  • No people: no author, reviewer or leaderboard. The unit is the area.

Caveats

  • The upstream scripts/ci/set_assignees.py caps labels at 10 per PR, ranked by how much of the PR each area accounts for. Very wide PRs lose their tail labels, so area counts are slightly lossy at the edge.
  • A PR whose STM32 label was removed before it closed is not returned by a label-filtered listing, so historical membership is marginally undercounted.
  • The history is rebuilt from timestamps. Review-state and staleness are only known for the present, so past days do not carry them.
  • This page is authoritative; any badge pasted in a PR comment is cached and may lag.
